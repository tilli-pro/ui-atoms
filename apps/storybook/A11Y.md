# Storybook accessibility

`pnpm --filter storybook test:stories` runs axe over every story with
`parameters.a11y.test = "error"`: any violation fails the suite.
This document records how each accessibility defect found in the ported
components and their stories was classified and fixed. Every finding below
was a real defect: **there are no per-story rule disables** (target: none,
met).

## Rule disables

None.

## Component fixes (`packages/ui-atoms`)

Each fix below has a covering vitest assertion (see the referenced test
file) and ships under `.changeset/w2-a11y.md`.

| Component | Rule | Defect | Fix |
|---|---|---|---|
| `styles.css` (`--muted-foreground`) | `color-contrast` | `oklch(0.556 0 0)` (#737373) is 4.34–4.46:1 against the near-white surfaces it renders text on (`bg-muted` #f5f5f5 — including `kbd`, which renders on that same background — alert's error tint, frame's subtle panel bg) — under the 4.5:1 AA text threshold in every case it was exercised. | Darkened to `oklch(0.5 0 0)` (#636363), which clears 4.5:1 against #f5f5f5 with margin (5.51:1) and therefore against every lighter surface too. Dark theme's `--muted-foreground` (not exercised by the light-only test suite) is unchanged. Test: `__tests__/styles.test.ts`. |
| `styles.css` (`--destructive-foreground`) | `color-contrast` | Set equal to `--destructive` (#e7000b), which is 4.14–4.15:1 against the destructive/8–10% tints it's paired with as text (badge's `error` variant, a hand-rolled error box) — under 4.5:1. | Darkened to `oklch(0.5 0.245 27.325)` (#ca0000), 5.03–5.20:1 against those tints. `--destructive` itself (icon fills, solid backgrounds — never text axe checks) is untouched. Test: `__tests__/styles.test.ts`. |
| `tabs` | `color-contrast` | The default variant's inactive-tab text used `text-muted-foreground/72` on `bg-muted` (#f5f5f5) — 2.67:1. No darkening of the base token closes that gap at 72% alpha (even a very dark gray stays under 4.5:1 once blended to 72%). | Dropped to full-strength `text-muted-foreground`, matching the `underline` variant's existing (passing) treatment. Test: `__tests__/components/tabs/index.test.tsx` (new file). |
| `calendar` | `color-contrast` | Weekday headers and outside-month day buttons used `text-muted-foreground/72` — 2.81:1 against white. Same defect and same fix as `tabs`. | Weekday/week-number headers and the outside-month day-button variant go to full strength. `in-data-disabled:text-muted-foreground/72` is **left alone**: WCAG 1.4.3 exempts text that is part of an inactive control, and a real `disabled`/`aria-disabled` day is exactly that. Test: `__tests__/components/calendar/index.test.tsx`. |
| `select` (`SelectTrigger`) | `button-name` | `role="combobox"` (set by base-ui's `Select.Trigger`) has `nameFrom: author` per the ARIA spec — axe's `button-name` check does not credit the trigger's own visible placeholder/value text as an accessible name for that role, even though a sighted user sees it. | `SelectTriggerPrimitive` generates an id via `useId()`, threads it through a new internal `SelectValueIdContext` so `SelectValuePrimitive` claims it, and sets `aria-labelledby` on the trigger pointing at its own `SelectValue` child — no change needed at any call site. An explicit `aria-label`/`aria-labelledby` on the trigger overrides this (verified). Test: `__tests__/components/select/index.test.tsx`. |
| `combobox` (`ComboboxTrigger`) | `button-name` | The trigger is icon-only (`aria-hidden` chevron), no text of its own — a plain missing-`aria-label` defect, the same pattern as an icon-only `Button`. | Default `aria-label="Toggle options"`, overridable via the normal `aria-label` prop. Test: `__tests__/components/combobox/index.test.tsx`. |
| `slider` | `label` | Each thumb renders a native `input[type=range]` with no accessible name — `Slider`/`SliderPrimitive` had no way to reach `Slider.Thumb`'s `aria-label`/`aria-labelledby`/`getAriaLabel` props at all. | `aria-label`/`aria-labelledby` on `<Slider>` are now forwarded to every thumb; a new `getAriaLabel` prop (`(index) => string`) forwards to `Thumb`'s own prop of the same name, for range sliders where each handle needs a distinct name. Test: `__tests__/components/slider/index.test.tsx` (new file). |

## Story fixes (`apps/storybook/src/stories`)

Demo-markup defects — missing/broken labels, hardcoded low-contrast inline
colors, and one bad composition — with no change to `packages/ui-atoms`.

- **`checkbox.stories.tsx` (`With Description`)**, **`currency-input.stories.tsx` (`With Min Max`)**, **`form.stories.tsx`** (both stories), **`input.stories.tsx` (`With Label`)**, **`switch.stories.tsx` (`With Label`)**, **`textarea.stories.tsx` (`Max Length`)** — `color-contrast`: hand-rolled helper/description text hardcoded `color: "#888"` (3.54:1 on white), inline in the story, not from a shared component class. Darkened to `#666` (5.74:1). (`checkbox`/`switch`'s *Disabled* stories already used `#888` next to a genuinely `disabled` control and were never flagged — WCAG exempts inactive-control text — so those are untouched.)
- **`switch.stories.tsx` (`With Label`)** — `aria-toggle-field-name`: all three `<Switch>` elements relied on visual proximity to an adjacent `<p>` for their name — no `<label htmlFor>`, no `aria-label`/`aria-labelledby`, so each toggle had none. Gave each label paragraph an `id` and pointed the matching `<Switch>`'s `aria-labelledby` at it (`Switch` already forwards arbitrary `aria-*` props to the underlying `input`; no `packages/ui-atoms` change needed).
- **`form.stories.tsx` (`With Validation`)** — the hand-rolled error box used `color: var(--destructive)` (4.00:1 on its own tint) instead of the token meant for readable destructive text; switched to `var(--destructive-foreground)` (now darkened, see above).
- **`select.stories.tsx`**, **`combobox.stories.tsx`** — no story change: both fully resolved by the component fixes above (every failing story used the shared `SelectTrigger`/`ComboboxInput` composition, unmodified).
- **`currency-input.stories.tsx` (`Default`/`Euro`/`Disabled`)**, **`number-field.stories.tsx` (`Default`/`Disabled`)** — `label`: no `<label>` at all, unlike the same files' already-passing `WithMinMax` story. Added an `id` + `<label htmlFor>` pair per story, mirroring that pattern exactly.
- **`slider.stories.tsx`** (all 4 stories) — `label`: no accessible name on any thumb. Added `aria-label="Value"` (`Default`/`Disabled`), `aria-label="Volume"` (`WithLabels`, matching its own visible text), and `getAriaLabel` for the two-thumb `Range` story (`"Minimum price"`/`"Maximum price"`). `WithLabels` also hardcoded `color: rgb(170, 170, 170)` (`#aaa`, 2.32:1) for its "0%"/"100%" captions — darkened to `#666`.
- **`otp-field.stories.tsx` (`Default`)** — `label`: no label at all. `OTPField.Input` reads its accessible name from the enclosing `Field`'s registered label (base-ui's own `useLabelableContext`), not from an `aria-labelledby` passed straight to `OTPField` (that prop labels the *group*, and is deliberately not threaded down to the individual slots — confirmed by trying it first: it left every slot unlabelled). Wrapped in `Field`/`FieldLabel` from `@tilli.dev/ui-atoms/field` instead, per base-ui's own dev-mode warning ("Use a `<label>` or `<Field.Label>` to label the OTP field").
- **`progress.stories.tsx`** (all 3 stories) — `aria-progressbar-name`: no `ProgressLabel`. Added one per story (`"Upload progress"`, `"Progress"`, `"Loading"`) — `ProgressLabel` self-registers via base-ui's `Progress.Root` context, so no other wiring was needed.
- **`command.stories.tsx` (`Default`)** — `aria-required-children`: `CommandEmpty` (`role="status"`) was nested inside `CommandList` (`role="listbox"`), which only allows option/group children — a composition habit carried over from the old cmdk API this was ported from (CMD-2), where `CommandEmpty` *was* meant to be a child of the list. Moved to a sibling of `CommandList`, matching base-ui's own composition.
- **`table.stories.tsx` (`Large Dataset`)** — `scrollable-region-focusable`: the demo's `overflow-y: auto` wrapper `<div>` around the table had no way to reach it by keyboard. Added `tabIndex={0}`, `role="region"`, `aria-label="Invoices"`.
